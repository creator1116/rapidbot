# Testing

## Unit and vector tests

```sh
cargo test --workspace
```

Several tests read vectors generated by running vanilla code (see
[porting.md](porting.md)). The generated files are checked in, so the tests
run without a JDK. Regenerate them after a version bump:

```sh
python tools/gen_packet_ids.py 26.3     # packet IDs
python tools/extract_blocks.py 26.3     # block data, attributes, entity classes, Mth tables
python tools/extract_items.py 26.3      # item components and decoder vectors
python tools/gen_clip_vectors.py 26.3   # ray cast vectors
```

## Live tests on a local server

Unit tests cannot tell you what a server makes of the bot. For movement and
interaction changes, run it against a local server.

A vanilla 26.3 server works for basic checks. Set `online-mode=false` and
`white-list=false` in `server.properties`.

To test against an anticheat, use a Paper server with an anticheat plugin
and ViaVersion (anticheats often trail the newest game version; ViaVersion
lets the 26.3 client join an older server). Turn on the anticheat's verbose
or alert output so flags appear in the console.

Enable RCON to script the server from tests:

```properties
enable-rcon=true
rcon.password=rapidtest
rcon.port=25598
```

```sh
python tools/rcon.py "gamemode survival Walker" "tp Walker 0 100 0"
python tools/rcon.py stop
```

`tools/rcon.py` uses that port and password; they are for a throwaway local
server only.

## Examples

Always run bots with `--release`.

```sh
cargo run -p rapidbot-protocol --example ping -- localhost 25565
cargo run --release -p rapidbot-client --example join -- localhost:25565 Steve
cargo run --release -p rapidbot-client --example walk -- localhost:25565 Walker
cargo run --release -p rapidbot-client --example chat -- localhost:25565 Walker "hello" "/msg Walker hi"
cargo run --release -p rapidbot-client --example course -- localhost:25565 Walker 130
cargo run --release -p rapidbot-client --example dig -- localhost:25565 Walker 62 150 60
cargo run --release -p rapidbot-client --example fight -- localhost:25565 Walker minecraft:husk
```

| Example | What it does |
|---|---|
| `ping` | Server list ping |
| `join` | Joins and idles (offline name, or `--microsoft accounts/main.json`) |
| `walk` | Wanders like a person and logs suspected checks |
| `chat` | Types the given lines into chat |
| `course` | Walks along +x through water and ladders; glides when wearing an elytra |
| `dig` | Digs the listed blocks from where it stands |
| `fight` | Fights the nearest entity of a kind, or the nearest player |

## What to look for

- The server keeps the bot connected and does not move it back.
- The anticheat console shows no flags. Run with nothing heavy alongside:
  a busy machine makes ticks irregular, which shows up as timer flags that
  are not the bot's doing.
- The effect happened on the server (the block is gone, the mob is dead),
  not only in the bot's own view.

Say in your pull request what you ran and what you saw.
